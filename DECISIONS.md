# Decisions

The decisions that shape Nästa Stopp as it is, each with its reason. This is not a changelog. The
code and docs describe the app as it is now; the git history before the tag `v1.0` is an archive
and is not needed to work on the app.

## 1. Privacy and data

| Decision | Why |
|---|---|
| Only addresses, trip times, the trip kind (Pull-out / Pick-up / Drop-off) and the passenger's **first + last name** are kept from what is read. No phone numbers, middle names or other text, but for one exception the driver decided: a YouDrive trip's whole card, for the passenger display's trip card only (→ "The trip card on the passenger display"). | The trips are paratransit rides and may reveal health information. The name helps the driver find the right person; nothing else is needed. |
| The full name is shown **only on the driver's own screens** (review, route, floating panel). The passenger display gets **only the last names of the trips still to come**: the display itself shows the next stop's (beside its figure; said and shown large only when tapped there), and **the tablet's map writes each stop's last name under its pin** (on the page only, never sent to Google). Never a first name, never a trip done's name. A name is never in an announcement, a notification or "Previous trips", and never logged. `namesStayOnTheDriversScreens` guards this. | The car and the tablet are shared with other passengers: the driver first chose to show only who gets on or off now. He then chose to see every coming stop's last name on the map, to plan who is picked up where; the tablet sits beside him and the map is written, never said. |
| Screenshots are read in memory and never copied or stored. | Only the extracted text is needed. |
| The route expires **12 h after it was created** (checked on load, on resume and by an inexact alarm). Finished trips stay in "Previous trips" for 12 h, 24 h or 7 days (setting 116–118). | Short retention by default; the driver chooses how long to keep a history. |
| `allowBackup=false`, and the backup / data-extraction rules exclude everything. Route files live in `noBackupFilesDir`. | Nothing leaves the phone through backups. |
| No Firebase, analytics, crash reporting or Hilt. ML Kit's upload backend (`CctBackendFactory`) is removed from the merged manifest. | The app has internet access for YouDrive; this keeps ML Kit's own telemetry from using it. |
| Release builds log no addresses or OCR text (`util/DebugLog` logs in debug builds only). | Logs are readable by other tools on the phone. |
| **The driver's entrances are kept** (`route/Entrances`, Settings 259): for an address he chooses, the stopping point he pastes and how to get in, with the street, number and postal code (or town) as written, the time it was saved and last changed. Never a name. On the phone only (`noBackupFilesDir/entrances.json`), never logged, until he deletes them; only the point goes to the tablet, to draw the way. The address's own point stays on the stop, and where the stop's point came from (the geocoder) is not overwritten. | Google leads some addresses to the wrong side of the building or the wrong yard. The driver asked to set the right place once and have navigation use it every day. A home's address without a name is the least that does it. |

## 2. Network

| Decision | Why |
|---|---|
| `INTERNET` is used for the YouDrive page, for the street map's download (only after the driver taps Settings 138) and for the passenger display's weather. `ACCESS_NETWORK_STATE` is removed. | These are the only features that need the network. |
| **The weather** comes from SMHI's open forecast (`snow1g`, no key) for one fixed point (Karlstad, 59.38 N 13.5 E), never the phone's position or an address. The phone fetches it every 30 min, only while a passenger display shows a route (the tablet connected, or the display open on the phone), and sends the temperature and SMHI's weather symbol in the snapshot. | The passengers see the weather of the area they ride through; the request names a fixed place, so it reveals nothing about the car. |
| **The tablet's Google map** (approved by the driver): the tablet, in the same car, takes the car's position from its own GPS (`TabletPosition`: high accuracy, every second, only while the passenger display is in sight, never in the background; the permission is asked on the first tap that wants the map). The phone sends each trip's point (the driver's entrance, else the address's; or its address; never a name) with the trips, and never its own position (Settings 209 and `LinkMessage.Where` are gone). The tablet draws Google's map with the Maps JavaScript API in a WebView of its own (`RouteMap`, `assets/route_map.html`: no device location, console silenced, no navigation away; the minute's map takes no touch, the driver's own map takes his) and asks Google's Routes API for the way (`RoutesApi`, basic tier; for the same stops in the same order, again only after 4 minutes **and** 1.5 km of driving; a way already given is used again for 15 minutes from within 1 km, in memory only), with the driver's own key typed on the tablet (208). Nothing is stored or logged. | The driver wants the way to the next stop on the tablet the way Google draws it. Google needs the two places to draw it; the driver's own key keeps the use and its free quota his. |
| **Google is asked only for what is new** (each is billed per request or per map made, not per use): one page and one map for the display's whole life, moved and redrawn, never made again (a look change recolours it, `setLook`); no 3D map or street-photo view is ever made (Google's own apps show them, 242/244); the way is asked again only when its stops or order change or the car has moved far; the route matrix only on "Suggest" (its elements are origins × destinations, so 5 stops ask 5 × 5 = 25). Addresses are found by Android's own geocoder, not Google's billed Geocoding API. Nothing from Google is stored: its terms let an app keep its coordinates for at most 30 days, and the app keeps them in memory for minutes. | Pans, zooms and moves are free; a new map, 3D map or panorama is not. Opening a map does not need a 3D map or street photos, and a way that has not changed does not need a new answer. |
| **One stop at a time in Google Maps, by its coordinates** (252–255): "Navigate here" opens Google Maps' directions to that stop alone (`dir_action=navigate`; Google Maps may still show the preview first), and "Street photos" opens Street View there (`map_action=pano`). Both are Google Maps URLs: no key, no cost on the driver's key, nothing sent by this app. The destination is the driver's entrance when he set one, else the address's point, never a search for its name; a stop with no point goes by its address. The batch of 10 keeps the address text unless the driver set an entrance. | A search by name can find another place with the same name; coordinates cannot. In the batch, Google's own routing to an address it knows often finds the right door better than a geocoder's point that no one checked, so a point replaces the text only where the driver set it. |
| **An entrance goes with the hospital's name.** Every word that names an entrance ("Huvudentrén", "Dialysentrén", "Entré 3") is written after the place's short name, as written ("C-Sjukhuset Dialysentrén"), and said after its name. | An entrance is a door, not a department: the driver and the passengers need to know which door. |
| **Every name is said once, and Centralsjukhuset is written "C-Sjukhuset"** wherever it is written on a screen (`Places.written`: the display, the driver's rows, the panel; never inside the trip card, which stays as written). A district or town already said in the street or place ("Centralsjukhuset Karlstad") is not said again (`GeoLogic.fullSpokenName`, whole words); a hospital typed with its town counts as the known place. The passenger's last name hides behind a small outlined figure (231): a tap shows it (236), a tap on it says it. | The display said "Centralsjukhuset Karlstad, Karlstad". The driver wants it short in writing, said once, and the name shown only when he asks. |
| **The trip card opens from the passenger's figure, laid out like YouDrive's details** (231 under the next stop, 234 beside every other trip with a card → 235): the card's lines become YouDrive's details layout (`TripCardText`: kind and time, name, estimated and negotiated times, kind and status, then Address, Phone number, Space Type(s), Mobility Aids, Fare amount, Compensation, Eligibility, Instructions), with the codes written out as YouDrive writes them (taken from the details windows the driver showed), their number kept as a count ("RU1" → "Rullstol 1": one wheelchair), and an unknown code kept as it is. The top line has no card sign. | The driver wants the card where the passenger is, for every trip, and readable the way he knows it from YouDrive. |
| **The trip card is small and drawn to be read at a glance** (235): about a quarter of the screen at first (36% of its width, at most half its height, 14 sp), over a lighter ground; a band in the trip's colour with its kind, time and status; the name beside a figure and the times beside a clock; each field with its own sign in a circle, the seats and mobility aids as chips, the instructions in a box with a yellow stripe. | The driver found the full-size card too large and plain; a small card with signs is read faster and leaves the display seen behind it. |
| **The trip card and the order list are windows the driver moves and sizes** (`FloatingWindow`: 261, 262, 264 on the card; 265, 266 on the list): a finger on the window's bar moves it; like any window, a side edge of its border makes it wider or narrower, its top or bottom edge taller or lower, a corner both, the opposite side staying where it is (width and height apart, never tied); two fingers anywhere on it move it and size it. The border has no marks. It never leaves the screen, and opens where and as big as he last left it (`WindowPlaces`, kept on the tablet in `SettingsStore`: the window's middle, width and height as shares of the screen, nothing else; a side never set is as its content is drawn). What it holds is laid out again at each size, its text at its own size (no scaling). One finger still scrolls and taps inside it. A tap on the card does not close it: its × or a tap beside it does. The map keeps its way clear of the list on the side the list is on (`RouteMap.listAt`). | The driver wants each window where it hides least of what he looks at, at the size he reads best, set by touch from its edges like any window, without setting it again on every trip. Sizing both sides together from any edge felt wrong to him: a window is made narrower from its side, lower from its bottom. |
| **The stops of a way each have their own colour** (`AppColors.wayStops`, the same in both looks): its pin, the way on from it to the next stop (the lighter part after the stop looked at too), its letter in the driver's list; its trip's time under its pin. The way from the car to the first stop is grey. The stop looked at is larger, in a red ring, and no stop's own colour is red. The time is drawn on the page and never sent to Google. | The driver tells the stops and their legs apart at a glance, and sees each one's time where it is. |
| **The driver's order list moves trips smoothly and takes them off the way** (245, 268, 269): a trip is dragged by its handle at once, or by its line after a long press; it stays under the finger (its translation is computed from the list's own layout, so it never jumps when it changes place) and the others slide out of its way. × takes a trip off the way on this map only (the phone's route keeps it; opening the map again brings it back); "+ Earlier" adds the trip before the way, as + adds the one after. The trip picked in the list is the one looked at: the red ring, the minutes to it, and Google's apps (242, 244). | The drag shook and jumped one row on each swap. The driver wants to drop a trip from the way he is weighing, and to bring in the one before it, without changing the phone's route from the tablet. |
| **Phone numbers on the card are found at a glance**: large (1.3×), bold, in the highlight colour, each on a line of its own from its start, under one sign; in the instructions too. The instructions are a tile for each thing written (`CardNotes`): cut where the dispatcher cut them (a line end, a "/" with a space or an edge beside it, a full stop before a capital), never between two words or figures joined by "/". Whose a number is goes after it only when that is clear: one or two words of letters right before it ("Dotter 070…" → "070… Dotter"), or after it when the part starts with a number; a word between two numbers ("alt") goes after the second; anything longer stays a line of its own, as written. Every word is kept. | The driver calls while driving: the number must stand out and start the line. Dispatchers' notes vary from passenger to passenger; moving only what is surely a label keeps the note exact. |
| **One trip read twice is one stop; the same address at another time is another trip** (`AddressExtractor.isSameTrip`, used where an image is read, where two images meet, and where the stops are added): an address repeated one after the other is merged only when nothing known differs, no two times, passengers or kinds. A field one of them lacks says nothing. | Two trips to the same hospital in a row were merged, and one was lost. An extra stop the driver sees in the review; a missing one he does not. |
| **A geocoder point in another place is never taken** (`GeoLogic.choose`): a point must match the written postal code or the written town; else the next candidate is tried, and the stop stays not located rather than wrong. | An answer in another town was taken as the stop's point, so the tablet's map and "Navigate here" could go to the wrong town. |
| **A corrected stop opens Maps again** (`RouteController.finishEdit`): the review compares each stop's number and where Maps goes for it (its address, or the driver's entrance). | Correcting an address or an entrance kept Maps on the old place. |
| **No order ever drops a passenger off before picking them up** (`OrderPlanner.allowed`, `best`, `RouteController.reorder`): "Suggest" never keeps such an order as the best, and the phone refuses one from the tablet. When the order shown has no way or cannot be used, the best one is still put up, without a saving to compare. A passenger with two trips in a day may be dropped off first when already in the car (more drop-offs than pick-ups). | The suggestion could keep a forbidden order as "the best already", and the tablet's check was the only one. |
| **The map asks again after a failure, and never shows an old way** (`RouteMap`): no way came, it is asked again after 30 s even when the car stands still, unless Google refused the request itself (a 4xx answer other than "too many"), which would be refused again; a way is reused only while it holds (15 min, within 1 km), on the driver's map too. | A failed request left the map without a way at a stop; the driver's map could show a way asked for from far away. |
| **The tablet keeps the last trips only for a short break** (`DisplayLinkClient`): 2 minutes after the link breaks they are cleared, at once when the display is left or another phone connects; the trip card closes when the link breaks, and the map's way is asked only while connected. The phone sends nothing before the tablet says it is a passenger display of the same protocol (`LinkProtocol.isDisplayHello`), and the tablet counts the link, keeps the device and takes its messages only once the phone answers as a controller (`isControllerHello`). This checks what each end says it is; it is not an authentication. | Old trips stayed on the display as if current, and any paired device that opened the channel received the trips and their cards. A short hiccup still keeps the passengers' screen. |
| **On the bottom line only the clock is large.** The next stop's time, "Därefter", the trip after it and their marks are small (half as tall and half as wide as before: a quarter of the room), and each of the three yellow arrows has two chevrons. | The driver asked for it: the clock is what the passengers read; the times beside it are for a glance up close. |
| **The trip card on the passenger display** (→ 235): a YouDrive trip's whole card, as written (names, phone numbers, codes, fees, notes), goes with the route (`Stop.card` → `DisplayItem.card`) and shows on the display only when the driver taps the card sign, until he closes it. The privacy note in Settings says so, and that the Google map's use may be billed beyond Google's free monthly use. Never said, never in an announcement, a notification, "Previous trips" or a log. | The driver wants the instructions, the ward and the codes at hand on the tablet. The tablet is beside him; the passengers sit far behind and do not touch it, so behind a tap the card is his alone. |
| **Phone numbers on the trip card are read at a glance**: in a light weight, a little apart, in groups of 3, 4 and 3 with a small no-break space ("073 8669 883", `TripCardText.spacedPhone`; a +46 number as dialled in Sweden; a number of another length 3, 4, then threes, never one digit alone). | The driver reads them while driving; bold digits run together and a number in one block is easy to misread. |
| **The display's moving parts never cross.** The minute's own moments wait while the display is busy (a trip shown large, the strip out, a page away from the next stop, a card open: `Moments.paused`). As the time grows, the bottom line beside the clock goes at once (`lineBack`). The next stop's time breathes inside its own width and grows into place from smaller when the stop changes. The hidden map's WebView is not drawn; one frame loop lights all the arrows; a still colon runs no animation; fast values are read only where they are drawn. | The driver saw the clocks move over each other and the display stutter. Two times moved at once, the time beside the clock breathed 20% wider than its room and sprang to 1.5×, and the hidden full-screen map was drawn with every frame. |
| **A town is never guessed.** The rule "a place without a town takes the list's most common town" is gone. A place written without a town or postal code is looked for in Värmland only and taken only in one town (`GeoLogic.inOneTown`); `Places.KNOWN` knows a few (Centralsjukhuset → Karlstad); otherwise the driver adds the town and `PlaceMemory` keeps it for that place (places without a house number only, never a home's address or a name). | YouDrive wrote "Centralsjukhuset huvudentrén," without a town on a day of trips in Kil, and the app put the hospital in Kil, showed it and said it. A wrong town sends the car to the wrong place. |
| **Place names** (`Stop.place`, `core/parse/Places`): the place YouDrive writes before the street (or instead of one) is kept and shown on the driver's screens. The passenger display shows and says only a place of care's own name (hospital, health centre, dental care), never a department or a home's name; Centralsjukhuset is written "C-Sjukhuset" and said "Centralsjukhuset, huvudentrén, Karlstad" (`DisplayItem.said`). The tablet's map gets the street, not a home's name. | The driver asked for it. Other passengers see the display, so a care home or a department would tell them about someone's health or home. |
| **The map's page grows and fades the map itself** (`reveal` / `conceal` in `route_map.html`, CSS); Compose never scales or fades the map's WebView, and the map is made only once its page has a size. What keeps the map or the way from coming (Google's script not loaded, no map pictures, a page error, the Routes API's HTTP answer) is shown small under the map (233), never logged. | On the tablet the map stayed black while the minutes and distance showed. A WebView scaled and faded by its parent's layer can stay blank, and a map made at no size can too; the line under the map says what is wrong if it still does not come. |
| **The travel time** is read from Google Maps' own navigation notification (`nav/MapsNavigationListener`, a notification listener the driver allows in Settings 203). Only Google Maps' ongoing notification is read, and only its numbers are kept: the minutes left (or the arrival time turned into minutes) and the distance. Nothing is stored or logged; the value lives while the notification does. | Google Maps already knows the route and the traffic. Reading its notification needs no online service, no position and no Maps window on the display. |
| `res/xml/network_security_config.xml` adds the public **Telia Root CA v2** (from the Mozilla store) as an extra trust anchor for `regionvarmland.se` only. | The site chains to that root, which Android 13 and older do not ship, so YouDrive would not load. TLS verification stays complete: untrusted certificates are refused, and there is no `proceed()`. |

## 3. Location, the current street and the speed

| Decision | Why |
|---|---|
| Location is asked at "Start route" (and in Settings 119), **while in use only**. `ACCESS_BACKGROUND_LOCATION` is removed from the merged manifest. | It is needed only while the driver is on a route with the app open. |
| Positions feed `CurrentStreet` (the street and the speed) **and nothing else**. They never move the route on, and are never stored, logged or sent. Only the driver's Next advances. | Every announcement follows a driver action. An automatic advance would speak without a tap, and consecutive stops at the same place would be skipped. |
| `StreetService` uses the system `LocationManager`: the GPS provider when precise location is allowed, high accuracy, a fix every 2 s, also when standing still. | "Balanced" positions come from Wi-Fi and masts, 30–60 m off and without a speed, which names the wrong street. No Play services location library is needed. |
| **The street name is never invented.** With the offline map, `StreetMatcher` takes the nearest named road within 30 m. A road across the heading counts 25 m farther once the car moves faster than 3 m/s. Positions less exact than 25 m are not used. No road means no name. | At a crossing the road driven along must win over the road crossed. A wrong name is worse than none. |
| Without the map, the geocoder's street counts only when its address lies within **40 m** (`StreetLookup.pickNear`); otherwise only the area is shown. Lookups are throttled (≥ 8 s and ≥ 35 m apart, retry after 30 s) and run only while something shows the street. | The nearest address is often on a side street. |
| A new street needs **two agreeing readings** (`StreetTracker`); without any road for 20 s the name is cleared. | One stray position at a crossing must not change (or say) the name. |
| **Offline street map** (Settings 138 / 139): the named roads for cars in Värmland, from OpenStreetMap through the Overpass API. 48 fixed tiles over the region (with a margin), one at a time with a 1 s pause. The answer is read as a stream and saved as a compact binary file in `noBackupFilesDir/streetmap/`. A new download replaces the file only when complete. | Exact road names without sending the position: the requests name the region, never the car. The map lives on the phone, not in the app package. Attribution: © OpenStreetMap contributors (ODbL), shown in Settings. |
| Each finished tile is kept in `streetmap/parts/` until the map is built, so a download that stops continues from the tile where it stopped ("stopped at part n of 48: tap to continue"; parts older than 14 days are fetched again). A tile is tried 8 times over about 5 minutes (pauses of 10–60 s), alternating overpass-api.de and overpass.kumi.systems, and Settings says "the server is busy, waiting" meanwhile. | The public Overpass servers answer 429 / 504 in bursts; one busy answer must not throw away the tiles already fetched. |
| The speed is the GPS speed, or is worked out from two exact positions (both ≤ 20 m, 0.5–10 s apart). It is shown only when fresh (≤ 10 s), as a number in its own circle on the panel. | Some fixes carry no speed; a stale speed would mislead. |
| The YouDrive WebView **never gets location**: `setGeolocationEnabled(false)` and every page prompt is denied (`theYouDrivePageNeverGetsTheLocation`). | The app's permission must not reach the dispatch site. |

## 4. Announcements (Swedish TTS)

| Decision | Why |
|---|---|
| Full announcement by default (setting 136): "Nästa stopp: Storgatan 14, Herrhagen, Karlstad. Därefter: Kungsgatan 5, Kronoparken." Settings 106 / 107 name both stops by district or town only. | The driver wants the whole address. The shorter forms remain for other routes. |
| **A passenger's name is never in an announcement.** A surname some lists put before the street is dropped (`RouteController.streetOf`). Only a tap on the next stop's last name on the passenger display says it. | Other passengers hear the announcements. |
| A spoken area never contains digits or the stop's street. A district ending in a street suffix ("…gatan") falls back to the town (`GeoLogic.isSafeAreaName`). Only towns in the bundled list are spoken. | Geocoder districts are sometimes street names; a town is safer than a guess. |
| A tapped trip on the passenger display is said with its time first. A trip still coming says where the car is going: "Klockan 8 och 05 ska vi till Hamngatan 7, Skoghall." ("Klockan 8" on the hour; the verb second, as Swedish word order wants after the time). A trip done says only its time and place: "Klockan 7 och 30: Järnvägsgatan 3B, Storfors." | "Ska vi till" is short, everyday Swedish and true for pick-ups and drop-offs alike, and it never sounds like the next stop ("Nästa stopp"); a trip done needs no verb. |
| The current street is said by itself each time it changes (`geo/StreetCaller`), queued after any announcement and never over it. The panel's speaker (4) or Settings 137 switch it off. Tapping the street bar says the street and area; tapping the next stop's street says its street and number. | The driver hears where he is without looking. |
| If the default engine lacks Swedish but Google's TTS is installed, the app uses Google's engine. An announcement requested while the engine starts is spoken only if it is less than 20 s old. The English repeat uses `en-US` when available. Maps is ducked while speaking. | Samsung's engine often has no Swedish voice. A late announcement would be wrong. |

## 5. Nothing appears on its own

Every dialog, toast, sound and Maps launch follows a driver action. The only exceptions are:
- YouDrive trip alerts (their purpose);
- the "open Maps" notification when Android blocks a background start at a batch change;
- the current street's name while "say the street" is on.

## 6. Reading addresses (`core/parse`)

- **Rules**: a line is an address when it has (a) a postal code with a town, (b) a street with a house number, or (c) a known town. Rule (a) needs at least 2 letters before the postal code, so a lone "65224 Karlstad" is joined to the street line above it.
- **Noise**: phone numbers, times, apartment parts ("lgh", "vån N", "N tr", "port", "portkod"), c/o names and money lines are removed. UI words (in Swedish too) reject a line. Short all-caps codes ("SP1, HLI") are skipped.
- **Truncation**: everything after the first "…" is dropped, and so is the cut word before it, unless it is a known town or a complete postal code.
- **OCR fixes** apply only inside the 5 postal-code positions, need at least 3 real digits and must give 100 00–989 99.
- **Joining lines**: the next line is joined when it starts with a postal code or is only a known town. The result must contain a house number.
- **Street words**: the suffix list plus `allé/alle/allen/vagen` (OCR without diacritics). A standalone suffix ("gata", "väg") counts only after another word. A street prefix word (Västra, Östra, Norra, Södra, Stora, Lilla, Gamla, Nya, Övre, Nedre, Yttre, Inre, Sankt, S:t) left at the end of the previous line is put back in front of the street, because ML Kit sometimes splits a row there.
- **Duplicates**: consecutive stops with the same street core, a compatible postal code and town merge, unless their kinds differ (a drop-off then a pick-up at one place are two stops).
- **Times**: a time on the address line wins; otherwise the nearest time above or below it, never past a neighbouring address. The direction is chosen **once per screenshot** by majority, together with the trip kind, so a trip never takes its neighbour's time or kind. A stop with nothing in that direction takes the time on its other side when the neighbouring trip does not use that line: YouDrive's start point has its time beside (read before) its address, while every trip card has it below. A first line that is only a time (the status-bar clock) is ignored.
- **Names**: the line right above the address when it is clearly a name; first and last name only.
- **Towns**: `assets/localities_se.txt` (677 names: all 290 municipalities, Värmland's localities and common postal towns), matched without case or diacritics.
- The parser never throws on a line (a per-line guard and a 40,000-line fuzz test).

## 7. Geocoding

- The system `Geocoder` (no internet library): candidates in order (at most 6), a result matching the postal code or town wins at once, a 15 s timeout, and "not located" otherwise. "Locate again" retries.
- After a match, the display text starts at the street the geocoder found, which drops a leading surname without guessing.
- A pasted point (`core/geo/Coordinates`: degrees-minutes-seconds, decimal with a point or a comma, or a Google Maps link) is taken only inside Sweden's bounds, so a swapped or mistyped pair is refused, not used.
- **Addresses Google does not know: Lantmäteriet's address register (proposed, waiting for access).** "Belägenhetsadress Nedladdning, vektor" for Värmlands län and Örebro län (GeoPackage, through Lantmäteriet's STAC API) would be imported into a local, searchable table on the phone (street, number, postal code, town, point; SWEREF 99 TM, EPSG:3006, turned into WGS 84, EPSG:4326, on import), updated on the driver's tap, and asked before Android's geocoder. Not started: it needs a Geotorget account, Lantmäteriet's approval of the purpose ("Adressökning och koordinatbaserad navigering i en transportapp inom Värmlands län och Örebro län"), the driver's review of the licence terms, and a sample file to learn the columns. No download is made and no terms are accepted before that.

## 8. The route and Google Maps

- Maps opens with at most **10 stops** per launch (its waypoint limit); the next batch opens at the end of each batch. `%20` for spaces, `%7C` between waypoints.
- Android blocks activity starts from the background, so a tap-to-open "Öppna Maps" notification is posted as well.
- Editing an active route re-launches Maps if the first 10 stops changed, and re-announces if the next stop changed.
- **Back** undoes the last Next: the previous trip becomes current, its history entry is removed, and Maps is re-launched only if its batch starts at the current trip (`batchStartStopId`).
- A **Pull-out** card is the start point (`RouteData.depot`): shown above the list, never sent to Maps or announced.
- "Sort by time" is a button, not automatic: the driver's order may be deliberate. Deletes show an Undo snackbar.
- "Avsluta" keeps the open trips in "Previous trips" as "not completed"; drivers often end instead of pressing Next at the last stop.

## 9. YouDrive

| Decision | Why |
|---|---|

## 12. The interface

- The UI is **English by default**, Arabic (RTL) and Swedish are available (101–103). Explanations stay Arabic while setting 104 is on. `values/` holds the Arabic strings, `values-en/` English and `values-sv/` Swedish; every key exists in all three.
- Design system in three layers (`Palette` → `AppColors` → `AppEffects`), Day / Night / Automatic looks (130–132). No colour values outside `Palette.kt` / `AppColors.kt`. `ThemeContrastTest` checks every text/background pair (WCAG 4.5, and 3 for borders and large text).
- Colours follow YouDrive's trip cards (green pick-up, white drop-off, grey start point) with taxi yellow for the next action.
- Explanations sit behind a small "?" (`HelpDot`), never inline.
- **Reference numbers** (a small number on every control) are **hidden by default** and switched on in Settings 105. The test tags / resource-ids `ref_<n>` are always present for UI Automator.
- Maps' picture-in-picture window covers the bottom-right third of the screen, and not every system moves it for `preferKeepClear`. So on the route screen the driving buttons (Back 77, Next 78, Repeat 79) sit in the left 60 % of the bottom bar in every language; Open Maps (80) and Edit list (81) sit on the right, where the small window only hides what is not needed while it is shown. End (82) sits in the top bar.
- The passenger display's title never splits a word: its size is capped so the longest word fits on one line. Only what changes each second (the seconds) uses equal-width digits; the hours, minutes and times keep the digits' own widths, so a "1" does not stand apart.
- Deliberately not built: calling or texting passengers (phone numbers are only in a YouDrive trip's card, shown on the tablet for the driver to read), a traffic ETA of our own (the display takes Google Maps' own), hiding the panel automatically while driving.

## 13. Build and delivery

| Decision | Why |
|---|---|
| One `app` module. Pure logic in `core/` (no Android imports, unit-tested). A manual `AppGraph`, no DI framework. Settings in `SharedPreferences`; the route and history as `kotlinx.serialization` JSON in `noBackupFilesDir`, written atomically. Hand-written vector icons. | Small, fast to test, few dependencies. |
| **R8 is off** for release. `proguard-rules.pro` keeps ML Kit's registrars for the day it is switched on again. Every release is checked with `dexdump` for `TextRegistrar`. | R8 full mode removed the constructors ML Kit creates by reflection, and text recognition failed on every image. Tests cannot catch it: they run un-minified code. |
| Release packages only `arm64-v8a` and `armeabi-v7a`. | The OCR native library is about 11 MB per ABI; the target devices are phones and tablets. |
| The release key is kept outside the repository (`keystore.properties` → `~/.nastastopp-signing/`); Hussam holds a private backup. Every build is signed with it. | Updates install over the previous build only with the same key. |
| **The version starts at 1.0, versionCode 1.** 1.0 is installed fresh (any earlier app removed first); from then on versionCode rises by one each build. The Releases of earlier builds were deleted, so no old tag clashes with a new version. | A clean start: no data or settings from earlier builds to carry over, so the app has no migration code. |
| Builds are published as **GitHub Releases** `v<versionName>`: `tools/publish-apk.sh` pushes the APK on a short-lived branch `apk-drop/v<version>`, and `.github/workflows/publish-apk.yml` creates the Release on the source commit and deletes the branch. APKs are never committed. A wrong Release is removed with `.github/workflows/delete-release.yml` (run by hand). | The signing key never reaches GitHub, and the repository does not grow with every build. |
| Every build is tested on the S20 Ultra by a second Claude session on the driver's laptop (adb), using invented screenshots (`testdata/`). | The cloud session cannot reach the devices. |
